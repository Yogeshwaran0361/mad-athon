# Security

## Threat model in one table

| Asset | Threat | Control |
| --- | --- | --- |
| Pay data and deductions | Someone sees or changes another person's record (IDOR) | Role checks on every action (reflection test fails the build if one is missing) and row-level checks in services (own records only for Employee/QA). Covered by `SecurityHardeningTests.Ids_belonging_to_someone_else_are_refused` and per-feature authorization tests. |
| Accounts | Password guessing, credential stuffing | PBKDF2 (ASP.NET Core Identity hasher); lockout after 5 failures for 15 minutes under a row lock; 10 attempts/min per address; same answer and similar timing for unknown accounts, wrong passwords and locked accounts. |
| Sessions | Stolen tokens | Access token 15 min, in memory only (never localStorage). Refresh token is 256-bit random, stored as SHA-256 only, sent as an HttpOnly, Secure, SameSite=Strict cookie scoped to `/api/v1/auth`, rotated on every use; reuse of an old token revokes the whole family and is audited. Password reset, deactivation and role change revoke every session. |
| History | Rewriting audit, task history or locked payroll | MySQL triggers, SHA-256 hash chain on audit events, and an application DB user without UPDATE/DELETE on those tables (`scripts/db/app-user-grants.sql`). `GET /api/v1/audit/verify` detects edits, deletions (middle or tail) and reordering. |
| Browser | XSS, clickjacking, sniffing | React escaping; strict CSP (`default-src 'none'` on the API, a self-only policy on the SPA via nginx); `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, COOP/CORP; `Cache-Control: no-store` on API responses; no `Server` header. |
| CSV/Excel exports | Formula injection | Cells starting with `= + - @` (and tab/CR) are prefixed with `'` in CSV and written as text in Excel. |
| Logs | Secrets or personal data leak | Serilog request logging records path, status and timing only (no bodies, query strings or tokens; the SignalR `access_token` query is never logged); EF never logs parameter values; correlation id ties a user's error to log lines. |
| Secrets | Committed or baked into images | None in the repo (`.env` and user-secrets are git-ignored; gitleaks in CI). Production reads them from AWS Secrets Manager. |
| Supply chain | Vulnerable dependencies | `dotnet list package --vulnerable`, `npm audit`, Trivy on images, CodeQL, all in CI; base images pinned. |
| Proxies | Spoofed client address | `X-Forwarded-*` accepted only from `ForwardedHeaders:KnownNetworks`. |

The full role/endpoint table is [AUTHORIZATION_MATRIX.md](AUTHORIZATION_MATRIX.md), generated by `EndpointSecurityTests` (regenerate with `RG_UPDATE_MATRIX=1 dotnet test --filter EndpointSecurityTests`).

## Audit hash chain

Each `AuditEvents` row stores `Sequence`, `PrevHash` and `Hash = SHA-256("v1" ␟ Sequence ␟ PrevHash ␟ OccurredAtUtc ␟ Actor ␟ EntityType ␟ EntityId ␟ Action ␟ DetailsJson)` (␟ = unit separator), computed by a BEFORE INSERT trigger that holds a lock on the single `AuditChainHead` row. The first row links to 64 zeros. Verification recomputes every hash in SQL and also checks that sequences have no gaps, each row links to the previous hash and the head matches the last row; it returns the first broken sequence and the reason (`hash`, `gap`, `link`, `head`). An attacker with full DBA rights could recompute the whole chain; to defend against that, export `headHash` from `/audit/verify` daily to a store the DBA cannot write (e.g. S3 with Object Lock) and compare.

## Reporting a vulnerability

Report privately to the repository owner; do not open a public issue with details.

## Known gaps

Listed in [DEFERRED.md](DEFERRED.md): access tokens are not individually revocable for their 15 minutes; no refresh grace period; no MFA or SSO; no password-reset-by-email flow (admins reset passwords); data-protection keys not persisted across instances; no WAF rules automated.
